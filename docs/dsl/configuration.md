# Configuration Reference

This page is the consolidated reference for every Spring Boot starter configuration property in
[`backend/dsl-starter/starter`](../../backend/dsl-starter/starter). It is generated by hand from the
`@ConfigurationProperties` classes under
`backend/dsl-starter/starter/src/main/java/cbs/nova/starter/config/` — the defaults below come from the
code, not from memory.

## Where configuration goes

The starter is a plain Spring Boot application, so every property below can be supplied through any of the
standard Spring configuration sources:

- `application.yml` / `application.properties` on the classpath or an external config location.
- Environment variables (relaxed binding: `cbs.nova.cache.defaults.max-size` becomes `CBS_NOVA_CACHE_DEFAULTS_MAX_SIZE`).
- JVM system properties (`-Dcbs.security.oidc.enabled=true`).
- The compose stack in `app/compose/app.yml` sets a few of them for the container (see
  [Temporal & server env](#temporal--server-env)).

## Conventions

- **`0`-or-`false` disables escape hatches.** Several features are *off by default and opt-in*: rate limiting,
  OIDC, and the runs retention purge are all disabled unless you explicitly turn them on. Numeric caps
  (`cbs.runs.max-*`, `cbs.runs.retention`) treat `0` (or a negative value) as "disabled".
- **Opt-in security defaults-off.** `cbs.security.ratelimit.enabled` and
  `cbs.security.oidc.enabled` both default to `false` so a fresh starter is behaviourally identical to the
  historical anonymous, unthrottled starter until an operator opts in.
- Types use Spring's kebab-case keys. Durations are ISO-8601 (`PT5M`, `PT2S`) or plain `ms`/`s` suffixes and
  are bound as `java.time.Duration`.

### `cbs.nova.events.mq`

Class: `MqEventProperties` (record). Optional RabbitMQ publisher for `DomainEvent` notifications.
The publisher is registered as a Spring bean only when `cbs.nova.events.mq.enabled=true`
(`@ConditionalOnProperty`, `MqEventConfiguration`); with the default `false` the starter starts
without a RabbitMQ broker and no publisher wiring exists. Routing-key resolution
(`MqEventProperties#effectiveRoutingKey`): if `routing-key` is set, it is used verbatim;
otherwise the publisher falls back to `topic + "." + eventType`; if `topic` is also blank, the
raw `eventType` is published.

> **Secrets / env-injected:** `cbs.nova.events.mq.*` carries **no** secret material — RabbitMQ
> credentials and broker URL are configured via the standard Spring AMQP properties
> (`spring.rabbitmq.host` / `port` / `username` / `password`), not via `cbs.nova.*`. Keep secrets
> out of source-controlled YAML; supply them via env vars or a secrets manager.

| Key | Type | Default | Effect |
|-----|------|---------|--------|
| `cbs.nova.events.mq.enabled` | `boolean` | `false` | Master switch. `false` (default) skips MQ publisher registration entirely. |
| `cbs.nova.events.mq.exchange` | `String` | — (unset; no initializer) | Target RabbitMQ exchange the publisher declares / publishes to (e.g. `cbs.nova.events.exchange`). |
| `cbs.nova.events.mq.topic` | `String` | — (unset; no initializer) | Topic prefix used to derive a routing key when `routing-key` is blank (`<topic>.<eventType>`). |
| `cbs.nova.events.mq.routing-key` | `String` | — (unset; no initializer) | Optional fixed routing key; overrides the `topic`-derived one. |
| `cbs.nova.events.mq.retry-batch-size` | `int` | `100` | Max events retried per pass by `MqDomainEventRetryTask`. Coerced to `100` if `<= 0`. |
| `cbs.nova.events.mq.retry-interval-seconds` | `long` | `30` | Fixed-delay between `MqDomainEventRetryTask` passes (seconds). Coerced to `30` if `<= 0`. |

### `cbs.nova.web`

Class: `CbsNovaWebProperties` (record). Web-layer global caps applied before any controller
reads the body. The `RequestBodyLimitFilter` (a `HandlerFilterFunction` wired onto every
functional router under `config/router/`) enforces this cap for `POST` / `PUT` / `PATCH`
requests. Read-only methods (`GET` / `HEAD` / `OPTIONS` / `DELETE`) bypass the filter.

- If a `Content-Length` header is present and exceeds the limit, the request is rejected
  immediately with `HttpStatus.PAYLOAD_TOO_LARGE` (413) and the
  `PAYLOAD_TOO_LARGE` `ErrorResponse` shape — the body is never read.
- If the header is missing (chunked transfer-encoding) or the client lies about the size, the
  underlying `ServletInputStream` is wrapped in a counting/limiting stream that throws
  `DslPayloadTooLargeException` as soon as a handler reads past the cap.

`DslPayloadSizeValidator` (`cbs.runs.max-input-bytes`) stays in place for the per-run /
preview / hierarchy / explain handlers — the filter is the **outer** ceiling, not a replacement.

Default `10485760` (`1024 * 1024 * 10`, **10 MiB**) was picked so that the largest existing
bulk-write fixture in the test suite still fits comfortably (the bulky fixture is a few KiB,
many orders below 10 MiB). Increase it for bulk-import / VCS-import workflows that ship large
bundles; set it to `0` to disable the global cap entirely (e.g. trusted-loopback deployments
or test contexts).

| Key | Type | Default | Effect |
|-----|------|---------|--------|
| `cbs.nova.web.max-request-bytes` | `long` | `10485760` (10 MiB) | Max HTTP request body size for any `POST` / `PUT` / `PATCH` under `/api/`. Oversized requests are rejected with HTTP 413 `PAYLOAD_TOO_LARGE`. `0` (or negative, normalised to `0`) disables the cap entirely. |

### `cbs.security.ratelimit`

Class: `CbsSecurityRateLimitProperties` (record). Opt-in token-bucket rate limiter for mutating DSL REST
endpoints (`/api/dsl/run/**`, `/api/dsl/preview/**`, `/api/dsl/explain/**`, `/api/dsl/reload`,
`/api/dsl/drafts/*/save`, `/api/dsl/drafts/*/publish`, `/api/dsl/drafts/*/discard`,
`/api/dsl/drafts/*` (DELETE), `/api/executions/*/cancel`). GET and actuator/health paths are always exempt. Bucket is
in-memory and refilled lazily per request.

| Key | Type | Default | Effect |
|-----|------|---------|--------|
| `cbs.security.ratelimit.enabled` | `boolean` | `false` | Master switch. `false` (default) applies no limiting. |
| `cbs.security.ratelimit.capacity` | `int` | `20` | Token-bucket capacity per client IP (reset to `20` if `<= 0`). |
| `cbs.security.ratelimit.refill-per-second` | `double` | `5.0` | Tokens refilled per second (reset to `5.0` if `<= 0`). |

### `cbs.security.oidc`

Class: `CbsSecurityOidcProperties` (record). Opt-in OIDC / JWT resource-server guard for the DSL REST API. The
JWT decoder itself is bootstrapped by Spring Boot from
`spring.security.oauth2.resourceserver.jwt.issuer-uri` (or `jwk-set-uri` / `public-key-location`); this prefix
only carries the cbs-nova toggle and the path lists.

| Key | Type | Default | Effect |
|-----|------|---------|--------|
| `cbs.security.oidc.enabled` | `boolean` | `false` | Master switch. `false` (default) installs no security filter chain; all endpoints stay anonymous. |
| `cbs.security.oidc.protected-paths` | `List<String>` | `["/api/dsl/**", "/api/executions/**"]` | Path patterns that require a Bearer JWT when enabled. |
| `cbs.security.oidc.permit-all-paths` | `List<String>` | `["/actuator/health/**"]` | Path patterns that stay anonymous in both modes. Even with OIDC enabled, `/actuator/health/**` answers without a token — the **body** the anonymous caller sees is still subject to the launcher property `management.endpoint.health.show-details=when-authorized` (env `HEALTH_SHOW_DETAILS`) and `show-components=when-authorized` (env `HEALTH_SHOW_COMPONENTS`), which strip the `components` / `details` blocks so probe detail is not leaked. Liveness/readiness group probes always return plain `UP/DOWN` regardless of `show-details`. Set both env vars to `always` for local dev / compose to opt back into full detail; supply a Bearer JWT in production (T752 hardening, see [docs/runbook.md §Health endpoints](../runbook.md#health-endpoints)). |

## `cbs.runs`

> **⚠️ The `cbs.runs` prefix is registered by two classes.**

Both **`DslRunRetentionProperties`** and **`DslRunsProperties`** declare
`@ConfigurationProperties(prefix = "cbs.runs")` — i.e. *neither* uses `cbs.runs.retention` as its prefix. They
are two separately-bound beans that happen to share the root prefix, and each requires its own
`@EnableConfigurationProperties` / bean registration.

They currently own **disjoint leaf keys and do not collide**:

- `DslRunRetentionProperties` owns the **retention purge** knobs (`cbs.runs.retention`, `cbs.runs.purge-interval`,
  `cbs.runs.purge-batch-size`).
- `DslRunsProperties` owns the **payload size caps** (`cbs.runs.max-input-bytes`, `cbs.runs.max-output-bytes`).

**Hazard to watch:** because both bind the same prefix, authoring a new `cbs.runs.*` key requires deciding which
class owns it, and a future edit to one class (e.g. adding a field whose relaxed-bind name shadows a field in the
other) would silently break the sibling's binding. Ideally these should be merged into one `cbs.runs` class or
split onto distinct prefixes (e.g. `cbs.runs.retention.*` / `cbs.runs.purge.*`).

### `cbs.runs` — retention purge (`DslRunRetentionProperties`)

Follows the project's opt-in pattern: the purge is **disabled by default** until a positive retention is set.

| Key | Type | Default | Effect |
|-----|------|---------|--------|
| `cbs.runs.retention` | `Duration` | `Duration.ZERO` (`0`) | How long finished runs are kept before being purged. `0` or negative disables the scheduled purge entirely (no job registered, nothing deleted). |
| `cbs.runs.purge-interval` | `Duration` | `PT1H` | How often the scheduled purge runs. |
| `cbs.runs.purge-batch-size` | `int` | `500` | Max rows removed per batched delete pass (keeps each schema/row lock small). |

The purge deletes each run's `dsl_run_transactions` child rows in the same batch window as its `dsl_runs` parent row (T305). Rows orphaned before that change (parent purged, children left behind) are not swept automatically — a full-table anti-join would take the row locks the batched purge is designed to avoid. Clean them up once, manually, in off-peak batches:

```sql
DELETE FROM dsl_run_transactions t
WHERE NOT EXISTS (SELECT 1 FROM dsl_runs r WHERE r.run_id = t.run_id);
```

### `cbs.runs` — payload size caps (`DslRunsProperties`)

Defensive caps applied before persistence / workflow submission.

| Key | Type | Default | Effect |
|-----|------|---------|--------|
| `cbs.runs.max-input-bytes` | `long` | `1048576` (`1024 * 1024`, `DEFAULT_MAX_BYTES`) | Max incoming run/preview request body size in bytes. Oversized inputs rejected with HTTP 413. `0` or very large disables the cap. |
| `cbs.runs.max-output-bytes` | `long` | `1048576` (`1024 * 1024`, `DEFAULT_MAX_BYTES`) | Max persisted run output JSON size in bytes. Oversized worker outputs are truncated on persist (run still completes normally). `0` or very large disables the cap. |

## Observability — OTLP export (T744)

T744 wires the starter into the compose observability stack (`app/compose/observability.yml` —
`otel-collector` :4317 gRPC / :4318 HTTP, jaeger :16686, loki, prometheus :9090 namespace `cbsnova`).
A fresh starter ships inert (every OTLP knob blank or `false`); operators flip the documented
values below to publish traces + metrics to a collector. Recommended endpoints:

| Environment | Trace endpoint | Metrics endpoint |
|-------------|----------------|------------------|
| localhost dev | `http://localhost:4318` | `http://localhost:4318/v1/metrics` |
| compose / k8s | `http://otel-collector:4318` | `http://otel-collector:4318/v1/metrics` |

Endpoint resolution order (matches `TracingConfiguration.resolveOtlpEndpoint`):

1. `cbs.nova.tracing.otlp.endpoint` (existing starter knob, T519 contract)
2. `management.opentelemetry.tracing.export.otlp.endpoint` (Spring Boot 4 standard)
3. `OTEL_EXPORTER_OTLP_ENDPOINT` env var (OpenTelemetry SDK standard)
4. nothing → starter SDK is a no-op (`OpenTelemetry.noop()`); no startup failure, no log spam

| Key / env | Type | Default | Effect |
|-----------|------|---------|--------|
| `cbs.nova.tracing.otlp.endpoint` | `String` | `''` (blank) | Trace endpoint (full URL). Blank disables the starter SDK unless the next two knobs resolve. |
| `management.opentelemetry.tracing.export.otlp.endpoint` | `String` | `''` (blank) | Spring Boot 4 standard trace endpoint, fed into the same resolution chain as a fallback. |
| `management.tracing.sampling.probability` | `double` | `1.0` | Sampler ratio; `0.0` records no spans, `1.0` records every span. |
| `management.tracing.baggage.correlation.fields` | `List<String>` | `[cid]` | MDC keys copied onto the active span as baggage/attributes. The starter already populates `cid` from `X-Correlation-Id` (`RequestIdFilter`, `DslRuntimeService`, `PieceCheckPipeline`) — leaving this as `[cid]` joins a Jaeger span back to the matching BFF log line. |
| `management.otlp.metrics.export.enabled` | `boolean` | `false` | Master switch for the OTLP metrics registry (`@ConditionalOnEnabledMetricsExport("otlp")`). Flip together with `url` to publish every existing Micrometer meter over OTLP/HTTP. |
| `management.otlp.metrics.export.url` | `String` | `''` (blank) | OTLP HTTP metrics endpoint (default URL when unset is `http://localhost:4318/v1/metrics`). |
| `management.otlp.metrics.export.step` | `Duration` | `1m` | Publish cadence. |
| `OTEL_EXPORTER_OTLP_ENDPOINT` (env) | `String` | `''` (blank) | OpenTelemetry SDK env var; same chain as above. |

**What is NOT changed by T744.** The existing prometheus scrape path (`/actuator/prometheus`,
`app/observability/prometheus.yml`) keeps working — `micrometer-registry-otlp` is added on top
of `micrometer-registry-prometheus`, both children of the same Micrometer composite. The
starter SDK remains the single trace export path (Spring Boot's
`OpenTelemetrySdkAutoConfiguration` backs off via `@ConditionalOnMissingBean` on
`TracingConfiguration#openTelemetry`).

**Trace verification.** With compose up, `make trace-smoke` curls one preview and queries
Jaeger; see [architecture-backend § Tracing in compose](../architecture-backend.md#tracing-in-compose-default-on)
for the end-to-end chain and the no-traces troubleshooting checklist.

## Temporal & server env

A few runtime knobs are wired through `@Value`/YAML rather than a `@ConfigurationProperties` class. Defaults come
from the starter source and the shipped `application.yml` files:

| Key / env | Type | Default | Effect |
|-----------|------|---------|--------|
| `temporal.connection-target` (env `TEMPORAL_ADDRESS`) | `String` | `127.0.0.1:7233` | Temporal frontend gRPC address used by `WorkflowServiceStubs`. |
| `temporal.execution-timeout` | `Duration` | `30s` | Workflow execution timeout set on launched runs. |
| `temporal.task-timeout` | `Duration` | `5s` | Workflow task timeout set on launched runs. |
| `server.port` (env `SERVER_PORT`) | `int` | `8080` | HTTP listener port (`starter-launcher` YAML: `${SERVER_PORT:8080}`). The `app/server` profile and the compose stack override this to `8090`. |
| `adminUiPlugin.temporalUiBaseUrl` (env `TEMPORAL_UI_BASE_URL`) | `String` | `''` (blank) | Base URL of the Temporal Web UI (e.g. `http://localhost:8233`). When set, the executions detail view renders a "View in Temporal" deep-link next to the Workflow ID. Blank disables the feature. |
| `adminUiPlugin.temporalNamespace` (env `TEMPORAL_NAMESPACE`) | `String` | `'default'` | Temporal namespace used when building the workflow deep-link. |

**Compose env overrides** (`app/compose/*.yml`) — the relevant keys the stack feeds the Spring app are
(`grep` cross-reference):

- `app/compose/app.yml`:
  - `SPRING_PROFILES_ACTIVE` (default `prod`) — selects the Spring profile.
  - `TEMPORAL_ADDRESS` (set to `temporal:7233`) — sets `temporal.connection-target` to point at the containerised
    Temporal server.
  - `MANAGEMENT_*` / `OTEL_*` observability env vars (tracing/logging endpoints and sampling) — Micrometer OTLP.
  - `SENTRY_DSN`, `KEYCLOAK_URL` — Sentry / Keycloak wiring.
- `app/compose/orchestration.yml` — `TEMPORAL_HOST` / `TEMPORAL_PORT` configure the **Temporal UI** service, not the
  Spring app; the app reaches Temporal via `TEMPORAL_ADDRESS` (`temporal:7233`).
- `app/compose/auth.yml` — documents the OIDC opt-in: `cbs.security.oidc.enabled=true` plus
  `spring.security.oauth2.resourceserver.jwt.issuer-uri=http://keycloak:8080/realms/cbs-nova` (see
  [`cbs.security.oidc`](#cbssecurityoidc)). Default is fully anonymous.
- `app/compose/postgres.yml` / `orchestration.yml` — `TEMPORAL_DB_PASSWORD` feeds the shared Postgres instance and
  the Temporal auto-setup; it is infra, not a starter property.

Because Spring uses relaxed binding, every documented key can also be supplied as an environment variable in the
UPPER_SNAKE_CASE form (e.g. `cbs.nova.cache.defaults.max-size` → `CBS_NOVA_CACHE_DEFAULTS_MAX_SIZE`).
