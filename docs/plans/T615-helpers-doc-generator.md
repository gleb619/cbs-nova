## Goal

The starter ships 50+ DSL-callable `@Helper` beans, discoverable at runtime via
`GET /api/v1/dsl/helpers` (`HelpersResponse`: `names` + `HelperCatalogEntry{name, description,
inputType, outputType, hasSideEffects, previewBehavior}`) and browsable in the Workbench — but
there is no committed reference doc for DSL authors (`docs/` has zero helper-table files).
Hand-writing one would drift; generate it instead, exactly the way `docs/openapi.json` works:

1. New cbs_cli command `helpers-doc` (follow `openapi_fetch.py` structure): GET
   `${BFF_BASE_URL}/api/v1/dsl/helpers`, render a markdown table (Name | Description | In | Out
   | Side effects | Preview) grouped alphabetically, one header noting generation instructions,
   write `docs/helpers.md`.
2. `make helpers-doc` target beside `openapi`; header comment in the generated file:
   "Generated by `make helpers-doc` (needs the stack running) — do not edit by hand."
3. Commit the first generated `docs/helpers.md`.
4. Optional stretch (only if trivial): `helpers-doc-check` diff guard mirroring
   `openapi-check`, wired as a separate `make` target (NOT into CI in this task).
