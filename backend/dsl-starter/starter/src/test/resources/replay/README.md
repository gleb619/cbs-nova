# Workflow Replay Goldens

JSON-encoded Temporal workflow histories used as regression baselines by
`WorkflowReplayGuardTest`. Each file is the verbatim output of
`io.temporal.common.WorkflowExecutionHistory.toJson(true)` after running the named generated
workflow on a `TestWorkflowEnvironment`.

| File | Process | What it covers |
| --- | --- | --- |
| `SampleProcess.json` | `SampleProcess` (linear) | Bare `@WorkflowMethod` returning a string; no helpers, no transactions, no signals. |
| `SimpleOrder.json` | `SimpleOrder` (compensation) | Workflow with a registered compensation closure; the run completes successfully, but the compensation path is part of the deterministic surface. |
| `SignalBranch.json` | `SignalBranch` (signal await) | Workflow that calls `ctx.awaitSignal(...)`; the recorded history contains a `WorkflowExecutionSignaled` event so replay unblocks the `Workflow.await` deterministically. |
| `ReplayMismatchCanonical.json` | `ReplayMismatchWorkflow.CanonicalImpl` (negative-control fixture) | Used only by the negative-control test, which replays this history against `ReplayMismatchWorkflow.MisorderedImpl` and asserts `NonDeterministicException`. |

## Regenerating

Goldens are generated by `WorkflowReplayGoldensGenerator` (one-off). Enable it with the system
property below and run the dedicated task. Note that Gradle does **not** forward `-D` flags from
the launcher JVM to the forked test JVM, so use one of these forms:

```bash
# Preferred: a tiny init script that wires the system property on the forked test JVM.
cat > tmp/t770-init.gradle <<'EOF'
gradle.projectsEvaluated {
  rootProject.allprojects {
    if (it.name == 'starter') {
      it.tasks.withType(Test).configureEach {
        if (project.hasProperty('cbsNovaT770Regen')) {
          systemProperty 'cbs.nova.t770.regenerate-goldens', 'true'
        }
      }
    }
  }
}
EOF
backend/dsl-platform/gradlew -p backend/dsl-starter :starter:test \
  --tests 'cbs.nova.starter.temporal.WorkflowReplayGoldensGenerator' \
  --init-script tmp/t770-init.gradle -PcbsNovaT770Regen=true --rerun-tasks
```

Without the property the generator is skipped (`@EnabledIfSystemProperty`), so the regular
suite never touches these files.

## Policy

- **Do not regenerate casually.** Any diff in these files means the generated workflow emits a
  different sequence of deterministic commands against the same input. That is exactly the kind
  of change that would explode live runs in production with `NonDeterministicException`.
- **Regenerate only when the change is replay-incompatible on purpose** (e.g. you reordered a
  step in a DSL flow that the existing golden would never accept). Always call it out in the
  commit message body — the guard exists precisely so accidental diffs cannot slip in unnoticed.
- The three chosen examples were picked to span the deterministic surface that `dsl-codegen`
  emits today: a linear flow, a flow with compensation, and a flow with a signal await. If new
  deterministic constructs are added to the DSL (timers, parallel branches, child workflows,
  …), add a matching golden here.
